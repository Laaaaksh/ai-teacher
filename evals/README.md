# RAG retrieval quality eval

`npm run eval:rag` runs `retrieval-eval.ts` against a real, committed PDF
fixture (`fixtures/electricity-basics.pdf`) — not a mock. It parses and
chunks the real file, embeds it with the real local MiniLM model, and runs
real hybrid retrieval and grounding for a handful of real questions with
known-correct expected source pages.

## What it checks

- **In-scope retrieval**: four questions, each with a known expected source
  page (one per chapter of the fixture — Current & Voltage, Resistance &
  Ohm's Law, Circuits & Kirchhoff's Laws), asserting the top retrieved chunk
  comes from that page.
- **Anti-hallucination gate**: one question the fixture does *not* cover
  ("capital of France"), asserting no retrieved chunk's cosine similarity
  reaches `DENSE_RELEVANCE_THRESHOLD` — it calls `isRelevant()` from
  `lib/rag/ground.ts` directly, so the eval and the production gate cannot
  drift apart.
- **Cross-language retrieval**: the Ohm's Law question asked in Hindi
  against the (English) fixture, asserting it still retrieves the correct
  page — this needs `SARVAM_API_KEY` (query translation; see
  `lib/rag/language.ts`) and is skipped with a clear `SKIP` line if the key
  isn't set.
- **Grounded answer + citations**: a full `ground()` call for an in-scope
  question, asserting the answer is marked grounded and carries at least
  one citation.
- **Grounded refusal**: a full `ground()` call for the out-of-scope
  question, asserting it returns `grounded: false` with the honest
  "not covered" message rather than an LLM-generated guess.

The last three checks need `SARVAM_API_KEY` (the chat/translate calls);
without it they print `SKIP` rather than failing, so the retrieval-only
checks (the majority) always run offline once the embedding model is
cached.

## Why this isn't part of `npm test`

The default suite (`__tests__/`) is fast and network-free by convention in
this repo (Sarvam calls are mocked — see `AGENTS.md`). This eval needs a
real ~23MB model download on a machine's first run (then cached under
`.cache/transformers/`, gitignored) and takes several seconds even warm —
that doesn't belong in the suite that runs on every save.

## Regenerating the fixture

`fixtures/electricity-basics.pdf` is generated by
`fixtures/generate-electricity-basics.ts` (original content, three short
chapters on basic electricity — current/voltage, resistance/Ohm's Law,
circuits/Kirchhoff's laws — written specifically so each question in the
eval has one unambiguous correct source page). Regenerate with:

```
npx tsx evals/fixtures/generate-electricity-basics.ts
```

## Tuning `DENSE_RELEVANCE_THRESHOLD`

`lib/rag/ground.ts` gates grounding on the best raw cosine similarity among
the retrieved chunks, not the fused BM25+dense rank score (see that file's
doc comment for why). Against this fixture, an on-topic query's best dense score
is consistently 0.55–0.85; an off-topic query's is under 0.1 — the current
threshold (0.32) sits with wide margin on both sides. If a future document
type or question style narrows that margin, re-run this eval after changing
the threshold to confirm it still separates in-scope from out-of-scope
correctly.
